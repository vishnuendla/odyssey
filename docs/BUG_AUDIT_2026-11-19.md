## 2. Root cause: the service worker caches the API

`odyssey-frontend/public/sw.js:43` guards only on `request.method !== 'GET'` and
origin, with a comment claiming API calls are never intercepted. `/api/...` is
same-origin and `GET`, so every API read falls through to the
stale-while-revalidate block at `sw.js:60-73` and is written to CacheStorage.

Proven in the live browser:

```
CacheStorage "odyssey-v2" contained:
  /api/notifications
  /api/notifications/unread-count
  /api/journals/my
  /api/journals/public
  /api/journals/search
  /api/journals/tags
  /api/storage/files/<id>.jpg
```

Consequences, all reproduced:

1. **Logout does not stick.** After `POST /auth/logout` (200) and a full reload,
   `/journals` still renders "My travel journals" and kate's data: the worker
   replays the cached `GET /api/auth/me` and `GET /api/journals/my`.
   Deleting the registration and caches and reloading lands on `/login`.
   Screenshot: `logout-still-authenticated.png`, then `logout-after-sw-purge.png`.
2. **Private data survives the session**, in a cache keyed only by URL — no user,
   no cookie, no `Authorization`. On a shared browser, the next account can be
   shown the previous account's library, notifications and bookmarks.
3. **Comments do not appear after posting.** `POST .../comments → 200`, the
   comment is persisted (a later authenticated `GET /api/journals/<id>` shows
   it), but `refreshJournal()`'s GET is answered from cache with the pre-comment
   body, so the count stays "0 so far" until a manual reload
   (`comment-after-post.png` vs `comment-after-reload.png`).
4. **Lists and flags are frozen** the same way: bookmark state, notification
   counts, public/gallery/search results, tag and location facets.
5. **Historical 403 loop.** Older clients took the CSRF token from the cached
   `/api/auth/csrf` *body* while the cookie had rotated, producing a permanent
   `403` that a retry could not fix. The current client derives the header from
   the cookie (fix already shipped), so the 403 no longer reproduces, but the
   cache that caused it is still installed.

The cache is only cleared by the "Reset this browser's session" repair path
(`src/services/api.ts` → `resetBrowserSession`). Normal logout does not clear it.

### Checked and found correct

- Private/hidden journal access: `JournalService.getJournalById` returns the same
  404 as a missing id (`JournalService.java:186-200`).
- Comment deletion checks journal ownership, comment ownership and admin role.
- Anonymous `GET /api/journals/public`, `/search`, `/tags`, profiles and storage
  files only; `/my`, `/bookmarks`, `/notifications`, `/api/admin/**` return 401.
- Public profile never returns email (`PublicUserDto`).
- Pagination is clamped (`size` 1..50, `page ≥ 0`) and sort fields are whitelisted.
- Storage path traversal (`..%2F..%2Fpom.xml`) returns 400.
- CSRF rejection now carries `code: csrf_invalid`; cookie-blocked browsers get
  explicit guidance.
- Refresh/verification tokens are stored only as SHA-256 hashes, single-use, with
  expiry; password reset revokes refresh tokens and bumps `tokenVersion`.
- Upload path traversal is blocked at the controller and again after
  `normalize()` in `StorageService`; filenames are UUIDs and content is
  magic-byte validated.
- `JournalQueryCountTest` still guards the journal DTO path (≤12 queries).

## 4. Fix plan

> **Status (19 Nov 2026):** Phase 0 is implemented and verified against the
> rebuilt Docker stack — `9cfb2ad`, `286e2f8`, `31abce4`, `7afae4b`. Finding 17
> (Host/CORS) was fixed separately in `a7db331`. Phases 1 and 2 are still open.

### Phase 0 — shipped

- **F0a** `JournalService.removeBookmark` now applies the `getJournalById`
  visibility guard; non-owners get 404 with no body leak.
- **F0b** `LocationRepository.searchVisibleByQuery` filters to public,
  non-hidden journals, caps at 10 rows, and blank/short queries return `[]`.
- **F1** `sw.js` excludes `/api/` from the fetch handler and `CACHE_VERSION`
  is `odyssey-v3`.
- **F2** `clearPerUserClientState()` drops list caches, drafts and cached
  `/api/` responses on login, register, logout and logout-all.
- **F3** `/journals/new` redirects to `/create`.

Verified in Firefox 160: CacheStorage holds only `odyssey-v3` with zero `/api/`
entries, a posted comment renders without a reload, logout survives a hard
reload (`/journals` → `/login`), and `/journals/new` lands on `/create`.
Live probes: anonymous private-place search returns `[]`, bookmark-removal IDOR
returns 404. Backend suite: 53 tests pass, including the two new regression
tests.

### Phase 0 — original scope (for reference)

**F0a. Close the bookmark IDOR (B1).**

`JournalService.removeBookmark` must not be a read path for other people's
journals. Either return `{ "bookmarked": false }`, or apply the exact guard from
`getJournalById` (`hidden`/`!public` + owner/admin → 404).

*Acceptance:* `DELETE /api/journals/{private-id}/bookmark` as a non-owner returns
404 with no title/content; the same call on your own bookmark still removes it.

**F0b. Lock down location search (B2).**

`LocationRepository.searchByQuery` joins `journal` and filters
`j.isPublic = true AND j.hidden = false`; add `LIMIT 10`; reject blank/1-char
queries with 400; keep the route public only if the filtered query is truly
public data, otherwise require auth.

*Acceptance:* the anonymous search that returned `Audit Secret Cove` now returns
`[]`; public journal places still resolve.

**F1. Never let the service worker touch `/api/`.**

`odyssey-frontend/public/sw.js`
```js
if (
  request.method !== 'GET' ||
  url.origin !== self.location.origin ||
  url.pathname.startsWith('/api/')
) {
  return;
}
```
Bump `CACHE_VERSION` to `odyssey-v3` so activation deletes `odyssey-v2`.
Keep `skipWaiting` + `clients.claim`.

*Acceptance:* after a reload, `caches.keys()` has no `odyssey-v2`, no
`/api/...` entry exists in any cache, and comment/bookmark/notification reads
reflect writes immediately.

**F2. Clear client caches on logout and account switch.**

- `AuthContext.logout`: after `authApi.logout()`, call a shared
  `clearClientCaches()` that (a) deletes `odyssey.cache.v1:*` sessionStorage
  entries, (b) deletes the app caches and unregisters the worker *if* an old
  worker is still controlling, (c) drops any `odyssey:draft:*` keys owned by the
  departing user.
- Do the same before `login()` when a different user signs in, so a shared
  browser never shows the previous account's list cache.

*Acceptance:* logout → hard reload → `/journals` redirects to `/login`; no
`/api` entries in CacheStorage; a second account sees only its own data.

**F3. Stop advertising a route that cannot exist.**

`odyssey-frontend/src/routes.tsx` — add above `/journals/:id`:
```tsx
<Route path="/journals/new" element={<Navigate to="/create" replace />} />
```
(React Router ranks static segments first; the explicit order is for readability.)

*Acceptance:* `/journals/new` lands on the editor with no `GET /api/journals/new`.

### Phase 1 — correctness (P1)

**F4. Comments endpoint contract.**
- Add `GET /api/journals/{journalId}/comments` returning
  `List<CommentDto>` with the same visibility rules as the journal
  (public journal → public; private → owner/admin only), **or** delete the
  route from `SecurityConfig` and keep comments embedded in `JournalDto`.
- `GlobalExceptionHandler`: map `HttpRequestMethodNotSupportedException` to
  **405** with `{message:"Method not allowed"}`, no stack trace at ERROR.
- Align security: comments on a public journal readable anonymously if the
  endpoint stays.

**F5. Map correctness.**
- `InteractiveMap.tsx:145`: `Number.isFinite(lat) && Number.isFinite(lng)`.
- `MapView` / `api.ts`: page `/journals/public?size=50` until `last`, merge,
  cache the merged list.

**F6. Gallery completeness.**
- Fetch `searchPublicJournalsPage` in a loop (size 50) until `last`, or add a
  dedicated `/api/journals/gallery` endpoint. Show the true total.

**F7. Notification failures.**
- Wrap `markRead`, `markAll`, `remove`, `load` in try/catch; optimistic update
  with rollback; destructive toast on failure.

**F8. Editor discard & drafts.**
- Discard resets form, tags, tag input, location and uploads before
  `clearDraft`.
- Scope the draft key to `user.id` and delete it on logout.

**F12. Framework errors must not be 500s (B6).**
- Add `@ExceptionHandler`s: `HttpRequestMethodNotSupportedException` → 405,
  `HttpMediaTypeNotSupportedException` → 415, `HttpMediaTypeNotAcceptableException`
  → 406, `MethodArgumentTypeMismatchException` → 400. Log at WARN without a stack
  trace.

**F13. Image ownership on delete (B3).**
- Record the uploader on each stored file; only delete a file when the caller
  owns it **and** no other journal still references the URL.

**F14. Config hardening (B4, B5).**
- Default `app.jwt.secure-cookies` to `true`; fail startup in the `production`
  profile unless it is explicitly `true`.
- Require `MAIL_MODE=smtp` in production and fail fast otherwise; never log token
  bodies.

**F15. Session refresh semantics (B7).**
- Run reuse detection only when `replacedByHash != null`; a token revoked by
  logout/password change returns a plain 401 without `revokeAllSessions`.

**F16. Timeouts and transaction boundaries (B8, B9, B11).**
- Set connect/read timeouts on Geocoding, Embedding and Chat clients (3 s / 10–30 s).
- In `AskService`, index and call providers outside the transaction, then open a
  short transaction to read embeddings.
- Send mail after commit (`TransactionSynchronization`/event) with SMTP timeouts,
  and report failure honestly.

**F17. Validation and visibility parity (B10, B12, B15, B16, B19).**
- `@NotBlank` on `ReactionDto.type` + `@Valid` on the controller argument.
- Gate uploads on verified email, add per-user rate limit/quota, reclaim orphans.
- Trust `X-Forwarded-For` only from configured proxies
  (`server.forward-headers-strategy`), otherwise use the container remote address.
- Distinguish "location absent" from "location explicitly null" in `updateJournal`.
- Apply the read-path visibility check to `removeReaction`.

### Phase 2 — polish (P2)

**F9.** Server-side "popular" sort (reaction count) or fetch-all before sorting;
remove the duplicate request when a filter change resets the page.
**F10.** Clear Leaflet `flyTo` timers on unmount/new selection.
**F11.** `aria-label` on remove-image and reset-map buttons.
**F18.** Paginate `GET /api/journals`, follower/following lists and notifications;
batch the per-user follow counts into one aggregate query (B13, B14, B20).
**F19.** Scheduled purge of expired/revoked refresh and verification tokens (B21).
**F20.** Evict `publicTags` on account deletion and tag mutations; raise content
to `MEDIUMTEXT` or add a byte-aware limit (B17, B22).
**F21.** Enumeration-safe registration, 201/204 status codes, one user lookup in
the JWT filter, bounded rate-limit cache, avatar URL allow-list (B23–B27).

### Regression checklist

1. Cold profile → login → `/journals` (200) → reload keeps session.
2. Logout → reload → `/login`; CacheStorage has no `/api/` keys.
3. Login as a second account in the same browser: no first-account data.
4. Post comment → appears without reload; count increments; delete removes it.
5. Bookmark/unbookmark → list and card state update immediately.
6. Notification mark-read persists across reload.
7. `/journals/new` → editor; nonexistent uuid → "Journal not found".
8. Create a journal at lat 0 / lng 0 → marker visible on `/map`.
9. 60 public journals → map and gallery show all 60 (or the documented cap).
10. Offline → shell still loads; online → every page revalidates.
11. Non-owner `DELETE /api/journals/{private-id}/bookmark` → 404, no body leak.
12. Anonymous `GET /api/locations/search?q=` never returns a private place.
13. `GET /api/journals/{id}/comments` → 405, not 500; malformed uuid → 400.
